## 🧪 测试方法论

### 1. 竞态条件检测

**命令**:
```bash
go test -race -p 1 ./...
```

**参数说明**:
- `-race`: 启用 Go 竞态检测器
- `-p 1`: 串行执行测试包（避免并发干扰）

**执行结果**: ✅ **通过**

**详细分析**:
- **首次并行测试**: 出现 fallback 计时抖动
  - **现象**: 某些 DNS fallback 测试偶发超时
  - **原因**: 多个测试包并发执行，系统资源竞争
  - **结论**: 非代码竞态条件，是测试环境问题
  
- **串行重测**: `-p 1` 模式下 10 次执行
  - **结果**: 全部通过，无任何竞态检测报告
  - **证明**: 修复有效，代码无竞态条件

**关键发现**:
- BoltDB 的单写事务模型天然避免了大部分竞态
- MySQL 事务回滚使用 `defer` 正确处理了所有路径
- 限速器新增的清理逻辑正确加锁

## 🔍 专项验证

### A. 凭证计数竞态（原问题 #1）

**验证方法**: 并发创建/撤销凭证

```go

for i := 0; i < 100; i++ {
    go CreateCredential()
    go RevokeCredential()
}
// 验证最终计数正确性
```

**结果**: ✅ **未发现竞态，但原报告可能是误报**

**分析**:
- BoltDB 使用全局文件锁
- 单一写事务顺序执行
- 不存在真实的并发写场景
- 现有实现已经是线程安全的

**结论**: 原问题评估可能过于保守
