# 多用户服务开发审核记录

分析基线：`5ce2b41`。实现由用户指定的三个 Sol Agent 分批完成，主 Agent 负责接口约束、代码审核、复审和集成验证。各批次在回传并通过复审后继续；验证范围见本文末尾。

## 架构约束

- `coremain` 组装账户服务、统计、API 与 DNS 监听器；已有 `pkg` 不反向依赖管理服务。
- 身份及凭证版本在进入执行链前确定，之后作为只读请求元数据共享。响应来源属于分支私有状态，跟随选中响应返回。
- 额度在进入缓存及上游前事务扣减；内部并发、fallback 与后台刷新不重复扣额。
- 准确用量与异步响应统计独立。统计失败不能恢复已消费额度，也不能使配额失败时继续放行。
- 管理端和用户端的资源隔离由服务端验证；前端路由不能替代授权。
- 新资源的初始化失败、停止监听、等待在途请求和关闭数据库都有实际调用路径。

## 最终集成验收

2026-09-11 在 macOS arm64、Go 1.26.6 上完成：

- `go test -mod=readonly ./...`、`go test -mod=readonly -race ./...`、`go vet -mod=readonly ./...` 全部通过；前两项各有 36 个包执行测试。
- 前端类型检查、15 项测试、格式检查和生产构建通过；另在与 CI 同主版本的 Node 22.23.2 下完成类型检查、15 项测试和生产构建。`go test -mod=readonly -tags ui ./web` 通过，UI 与无 UI 主程序均构建成功。
- `release.py` 原有 13 个目标全部通过 `CGO_ENABLED=0 go build -mod=readonly -tags ui`：Darwin amd64/arm64；Linux amd64、amd64 v3、arm v5/v6/v7、arm64、mipsle softfloat、mips64le hardfloat、ppc64le；FreeBSD amd64；Windows amd64。
- 实际二进制通过登录、角色隔离、路径 Token／Bearer／GET、无效报文不扣额、缓存命中计额、轮换、撤销、额度耗尽、到期与续期、停用、重启、旧 API 保护和 pprof 默认关闭验证。
- 实际 CLI 离线备份与恢复成功；文件权限为 `0600`。恢复后的管理员登录、账户停用、历史已用额度、有效设备凭证及撤销状态保持；新查询继续扣额。
- 浏览器完成管理员开户、用户登录、网页签发凭证、该凭证实际 DNS 查询和用量反馈；桌面及 390 像素手机宽度可用。最新嵌入界面已确认单点图表时间轴处于真实查询窗口内。

性能测量条件与结果见 [性能验证](performance.md)。所有集成上游使用本地服务，未依赖公共 DNS；未执行发布、部署或生产数据操作。跨平台构建验证不等于目标系统运行验证，Linux 内核 TLS、nftables、ipset 和系统服务管理仍需在对应部署环境验证。
