# 控制服务存储维护

控制服务使用单个 bbolt 数据库。数据库和备份包含密码派生值、会话与 DNS 凭证哈希、账户信息和用量记录，仍应按敏感数据保护。文件权限保持为 `0600`，备份不得上传到公共位置或通过不受信任的渠道传输。

首次用支持 UUIDv4 设备 token 的版本打开旧版 schema v1 数据库时，服务会在同一事务中创建 token 索引并升级到 schema v2。升级前应先离线备份；升级后的数据库不能再由只支持 schema v1 的旧二进制打开。

## 定期清理

`Store.Maintain(ctx)` 使用每批最多 256 条记录的小事务清理：

- 已到期或已撤销的面板会话，并同步删除用户会话索引；
- 超过 35 天的分钟用量；
- 超过 90 天的操作审计；
- 到期或撤销超过 35 天的 DNS 凭证，并同步删除凭证索引和有效凭证计数。

到期凭证在 35 天内保留，便于核对历史用量；它不能再轮换，用户需要创建新凭证。清理不会重置或改写当前配额。`Store.RunMaintenance(ctx, interval)` 可由服务生命周期调用：启动时先执行一次，此后按指定间隔运行，直到上下文取消或存储关闭。

## 在线备份

调用 `Store.Backup(ctx, path)` 可从一致的只读事务创建新备份。目标必须不存在；新文件权限为 `0600`。备份期间的长只读事务可能延迟数据库写入，磁盘较慢或数据库较大时应安排维护窗口，并确保源盘与目标盘有足够空间和稳定 I/O。

可用 `ValidateBackup(ctx, path)` 离线检查文件是否可读、必要 bucket 是否齐全以及 schema 版本是否兼容。不要对当前已打开的线上数据库路径执行离线验证；文件锁会使验证失败。

## 离线恢复

停止使用目标数据库的服务实例，然后执行 `Restore(ctx, backupPath, destinationPath)`。恢复会先验证备份，并且只创建不存在的新目标文件，不覆盖任何已有数据库。恢复成功后再用新的目标路径启动服务并检查账户、配额和 DNS 凭证。保留原数据库，直到恢复后的服务验证完成。
